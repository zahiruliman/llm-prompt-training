# Product Context

This document explains why this project exists, the problems it solves, and how it should work from a user's perspective.

## Problem Statement

Business Analysts (BAs) and System Analysts (SAs) at MIMOS use an internal tool, `AIDevX`, to help generate technical documentation. However, as average users of AI, they often provide simple, generic prompts which result in generic or incomplete outputs. This creates a bottleneck where the AI's potential is not fully realized, and significant manual rework is still required. There is a clear need to train them in advanced, structured prompting techniques to bridge this gap.

## How it Works

The project will deliver a complete set of training materials (in Markdown format) for a 1.5-hour workshop session. This content will break down complex prompt engineering concepts into simple, memorable, and practical techniques. Each technique will be explained with a rationale, a simple example, and a specific, role-based example of how to use it within `AIDevX` to create documents like a User Requirement Specification (URS) or System Requirement Specification (SRS).

## User Experience Goals

- **Clarity:** The content must be free of jargon and use simple analogies that resonate with the target audience.
- **Relevance:** Every example and technique must be directly tied to the daily tasks of a BA or SA and the `AIDevX` tool.
- **Empowerment:** Participants should leave the session feeling confident and capable of using `AIDevX` to produce high-quality work, not just generic drafts.
- **Engagement:** The content should be interesting and hold the audience's attention for the duration of the session.
